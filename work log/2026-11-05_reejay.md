## 4. The CI failure
- The first CI run (on `89289e6`) failed on 6 of 7 jobs. Cause: the `mcp` library released 2.3.0 and renamed `FastMCP`; our dependency had no upper limit. My local venv had 1.29.1, so it passed here.
- Fix: `mcp>=1.2,<2`, and CI now skips the `openshell` tests. Reproduced and re-verified in clean environments on Python 3.12 and 3.13 (ruff, format, mypy, 191 tests). A second clean-environment run also caught a CLI test that only passed because a runner was installed locally. [verified]
- macOS and Python 3.11 are confirmed only by the next real CI run.

## 6. Gotchas learned (also in COMPLETED.md)
- The adapter's `PYTHONPATH` must be absolute; a relative one fails with "No module named nemo_fabric_adapters.nat".
- A clean install gets `mcp` 2.x, which has no `FastMCP`. Pinned below 2. Lesson: reproduce CI in a fresh venv before pushing.
- Fabric hides the model's error body: a rejected key shows only a generic "workflow invocation failed".
- Background jobs from a non-interactive shell ignore Ctrl+C, so `ab ui` also shuts down on SIGTERM.
